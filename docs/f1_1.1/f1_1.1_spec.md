## 1. Technical Context & Goal
El objetivo técnico es definir la estructura, componentes y lógica visual de las **11 vistas/mockups** requeridas en el PRD v1.3.0. Se implementará la estética "The Intelligent Monolith" (Premium Glassmorphism), garantizando que el desarrollador frontend tenga todos los contratos de enrutamiento y validación necesarios.

## 2. Data Constants & Enums (CC-002)
Para garantizar la integridad y el databinding entre UI y Backend, se establecen los siguientes valores maestros:

| Constante | Valores Permitidos (Enum / Key) | Labels (UI) |
| :--- | :--- | :--- |
| **Paises** | `CO`, `US`, `CA`, `MX`, `VE`, `OT` | Colombia, EE.UU., Canadá, México, Venezuela, Otro |
| **Géneros** | `M`, `F`, `O` | Masculino, Femenino, Otro |
| **Verify Status**| `success`, `error` | Éxito de Verificación, Error de Verificación |

## 3. Component Architecture & Routing

### 3.1 Routing Strategy (Next.js App Router)
Se establecen las siguientes rutas para la navegación de la etapa:

| Vista | Ruta (Path) | Layout | Requisito PRD |
| :--- | :--- | :--- | :--- |
| Registro | `/auth/register` | `AuthLayout` | FR-1.1.1 |
| Login | `/auth/login` | `AuthLayout` | FR-1.1.2 |
| Recuperación (Request) | `/auth/recovery` | `AuthLayout` | FR-1.1.4 (A) |
| Recuperación (Reset) | `/auth/reset-password`| `AuthLayout` | FR-1.1.4 (B) |
| Verificación Enviada | `/auth/verify-sent` | `AuthLayout` | FR-1.1.8 (A) - Debe incluir aviso de spam. |
| Resultado Verificación | `/auth/verify-result` | `AuthLayout` | FR-1.1.8 (B/C)|
| Perfil (Editor) | `/profile` | `AppLayout` | FR-1.1.3 (A) |
| Perfil (Seguridad) | `/profile/security` | `AppLayout` | FR-1.1.3 (B) |
| Bloqueo de Cuenta | `/auth/blocked` | `AuthLayout` | FR-1.1.7 |
| Confirmación Baja | `/profile/delete` | `AppLayout` | FR-1.1.9 |
| Logout (Redirect) | `/auth/logout` | `None` | FR-1.1.5 |

### 3.2 Layout System
- **`AuthLayout`**: (Public/Auth) Fondo `surface-container-low` con panel central. Sin navegación persistente. Soporta `GlassCard` central.
- **`AppLayout`**: (Protected) Incluye el **`Header`** persistente y soporte para navegación lateral o de perfil. Fondo `surface-container`.

### 3.3 Component Enhancements
- **`StatusCard` (Interactive)**: Se extiende para soportar acciones condicionales:
    - **`ResendButton`**: Visible en `/auth/verify-result` cuando el estado es `Error`. Dispara el flujo de reenvío de token.
    - **`ConfirmDeleteButton`**: Visible en `/profile/delete`. Botón rojo vibrante con confirmación de seguridad para "Soft Delete". **UI Requirement**: Debe mostrar el texto informativo sobre los 30 días de periodo de gracia según PRD FR-1.1.9.
- **`Header`**: Barra superior en `AppLayout`. 
    - **UserNav**: Avatar con dropdown que incluye vínculos a `/profile` y la acción de Logout.
- **`GlassCard`**: Contenedor principal para `/auth` con:
    - `backdrop-filter: blur(12px)`
    - `background: rgba(var(--surface-rgb), 0.7)`
    - `border: 1px solid rgba(255, 255, 255, 0.1)`

## 5. Validation Schemas (Zod)
Para garantizar la integridad de los datos, se definen los siguientes esquemas técnicos:

- **`registerSchema`**: 
    - `first_name`/`last_name`: string (max 50, alpha).
    - `email`: email format.
    - `birth_date`: date (min 18 years).
    - `gender`/`country`: enum (matches Table in Section 2).
    - `password`: regex (8+, upper, num, special).
    - `terms`: boolean (true).
- **`loginSchema`**: 
    - `email`: email format.
    - `password`: string (min 8).
- **`profileSchema`**: 
    - `first_name`/`last_name`: string (max 50, alpha).
    - `birth_date`: date (min 18 years).
    - `gender`/`country`: enum.
- **`passwordChangeSchema`**:
    - `current_password`: string.
    - `new_password`: regex (8+, upper, num, special).
    - `confirm_password`: matches `new_password`.
- **`recoveryRequestSchema`**:
    - `email`: email format.
- **`resetPasswordSchema`**:
    - `new_password`: regex (8+, upper, num, special).
    - `confirm_password`: matches `new_password`.
    - `token`: hidden string (UUID format).
- **`deleteAccountSchema`**:
    - `confirmation`: literal string "ELIMINAR MI CUENTA".
    - `password`: string (for final security gate).

## 6. Interactive Logic & UX Detail
- **Theme Switching**: Via `next-themes`. Clase `.dark` en `<html>`.
- **Account Lock (Rate Limit)**: La pantalla `/auth/blocked` debe incluir textualmente la advertencia de espera de **15 minutos** según PRD FR-1.1.7.
- **Verification Mapping**: La ruta `/auth/verify-result` recibe el prop `status` vía query param (`?status=success` o `?status=error`).
    - Si `status=error`, el `StatusCard` muestra el `ResendButton`.
- **Loading States**: Todos los formularios deben mostrar un estado `submitting` (opacidad reducida en botón primario y cursor `wait`).
- **Logout Feedback**: Tras el cierre de sesión en `/auth/logout`, el sistema debe enviar un **Toast de Notificación** confirmando el éxito antes de redirigir a `/auth/login`.
- **Información de Spam**: La vista `/auth/verify-sent` debe contener instrucciones explícitas de revisar la carpeta de **Spam/Promociones** (PRD FR-1.1.8-A).
- **Micro-animations**: `Framer Motion` para transiciones de página entre rutas `/auth`. Transiciones de entrada `y: 20 -> 0`, `opacity: 0 -> 1`.

## 7. Test Strategy Details (Technical DoD)
- **Unit (Zod)**: Pruebas unitarias de los 7 esquemas anteriores (incluyendo Recovery y Delete). Casos de borde para edad e igualdad de passwords.
- **Integration (Navigation)**: Verificar que `/auth/verify-result?status=error` muestra efectivamente el botón de reenvío.
- **UI Robustness**: Verificación de visualización en Mobile (360px) vs Ultra-wide. Validación de contraste WCAG AA en Dark Mode.
